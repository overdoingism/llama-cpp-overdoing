# Benchmark 2026-10-13

Patch set: `0001-097-k1-v3`, `0002-097-f8-v3.2`, `0003-097-m4-v2` on rdna-boosts `v16-097cf33d9-r50`.  Written with Claude (AI).
Same setup as [2026-10-07](2026-10-07.md) (standard benchmark: 32K-token prompt, 512 greedy tokens, DFlash2 draft 5, q8_0 KV,
3 rounds).

## What changed

- rdna-boosts moved to a new upstream base (`097cf33d9`).  The three patches are the same code as on 2026-10-12, carried over to
  the new base; they apply in number order on the plain r50 release.
- The new base itself changes the numbers: plain r50 gives different greedy tokens from plain r8, and faster prefill and decode.

## Standard benchmark

| configuration | prefill t/s | decode t/s | ms / step | draft accepted |
|---|---|---|---|---|
| Q5 all off (plain r50) | 1124 | 50.84 | 56.46 | 334 / 876 |
| **Q5 all on** | **1959 (+74%)** | 50.59 | 56.43 | 333 / 886 |
| MXFP4 all off (plain r50) | 1344 | 60.82 | 46.16 | 330 / 899 |
| **MXFP4 all on** | **2397 (+78%)** | **66.20 (+8.8%)** | 46.50 | 346 / 821 |

- All on = `GGML_LF_KQ_BLAS=fp8` (KEEP 64), `GGML_LF_FA_FP8=1`, `GGML_LF_MXFP4_DIRECT=blaslt`, `GGML_LF_DRAFT_UB=512`.
- Every round gave identical tokens.  Run-to-run CV: prefill 0.2-1.2%, decode 1.0-1.6%.
- The patched build also carried two bit-identical commits that are now rdna-boosts PR #144 (DFlash with several slots); they do
  not act with one slot.
- With every switch off, the patched build gives exactly plain r50's tokens and speed (Q5 and UD-Q4_K_XL checked).
- MXFP4 on plain r50 was measured on 2026-10-14 with the same setup.

## Quality check on r50

Same check as before the K1 v3 release.  Qwen3.8-27B Q5_K_M (an uncensored fine-tune), `-ub 2048`, a 48,000-token context, then
400 tokens teacher-forced on the decode path; KLD of all on (`GGML_LF_KQ_BLAS=fp8`, `GGML_LF_FA_FP8=1`) against plain r50, compared
with the numerical floor of the same model (one-bit change in K).  Texts: Chinese = *Dream of the Red Chamber* (public domain),
English = the llama.cpp documentation concatenated (MIT).

| | KLD (without the largest token) | × floor | same top-1 (floor) | on r8, × floor |
|---|---|---|---|---|
| zh | 0.0024 | 1.29 | 97.50% (98.50%) | 1.32 |
| en | 0.0008 | 1.38 | 98.50% (99.50%) | 1.39 |

The new base does not change the quality of the patches.

# 2026-10-13 基準

本報告由 Claude（AI）撰寫。patch：`0001-097-k1-v3`、`0002-097-f8-v3.2`、`0003-097-m4-v2`，套在 rdna-boosts `v16-097cf33d9-r50`。條件與 [2026-10-07](2026-10-07.md) 相同（標準基準：32K token 的 prompt、greedy 生成 512 個 token、DFlash2 草稿 5、q8_0 KV、3 輪）。

## 改了什麼

- rdna-boosts 換到新的上游基底（`097cf33d9`）。三個 patch 的程式碼與 2026-10-12 相同，只是移植到新基底；在原版 r50 上照編號套用即可。
- 新基底本身就會改變數字：原版 r50 的 greedy 輸出與原版 r8 不同，prefill 與 decode 也較快。

## 標準基準

| 設定 | prefill t/s | decode t/s | 每步 ms | 草稿接受 |
|---|---|---|---|---|
| Q5 全關（原版 r50） | 1124 | 50.84 | 56.46 | 334 / 876 |
| **Q5 全開** | **1959（+74%）** | 50.59 | 56.43 | 333 / 886 |
| MXFP4 全關（原版 r50） | 1344 | 60.82 | 46.16 | 330 / 899 |
| **MXFP4 全開** | **2397（+78%）** | **66.20（+8.8%）** | 46.50 | 346 / 821 |

- 全開＝`GGML_LF_KQ_BLAS=fp8`（KEEP 64）、`GGML_LF_FA_FP8=1`、`GGML_LF_MXFP4_DIRECT=blaslt`、`GGML_LF_DRAFT_UB=512`。
- 每一輪的 token 都相同。輪間變異係數：prefill 0.2～1.2%、decode 1.0～1.6%。
- 量測用的 build 另含兩個逐位元相同的 commit（現為 rdna-boosts PR #144，多 slot 的 DFlash），單 slot 時不起作用。
- 所有開關都關時，加了 patch 的 build 與原版 r50 的 token 和速度完全相同（Q5 與 UD-Q4_K_XL 都驗過）。
- 原版 r50 的 MXFP4 於 2026-10-14 以相同條件補量。

## r50 上的品質檢查

與 K1 v3 發布前相同的檢查：Qwen3.8-27B Q5_K_M（去審查的微調版）、`-ub 2048`，先 48,000 token 的上下文，再走 decode 路徑逐 token 餵 400 個；比較全開（`GGML_LF_KQ_BLAS=fp8`、`GGML_LF_FA_FP8=1`）與原版 r50 的 KLD，並與同一模型的數值雜訊底（K 改一個位元）對照。文本：中文為《紅樓夢》（公有領域），英文為 llama.cpp 說明文件串接（MIT）。

| | KLD（去掉最大的一個 token） | 雜訊底的幾倍 | top-1 相同（雜訊底） | r8 上的倍數 |
|---|---|---|---|---|
| 中文 | 0.0024 | 1.29 | 97.50%（98.50%） | 1.32 |
| 英文 | 0.0008 | 1.38 | 98.50%（99.50%） | 1.39 |

換基底沒有改變這些 patch 的品質。
