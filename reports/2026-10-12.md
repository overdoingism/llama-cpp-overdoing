# Benchmark 2026-10-12

Patch set: `0001-a55-k1-v3`, `0002-a55-f8-v3.2`, `0003-a55-m4-v2` on rdna-boosts `v16-a55e952b8-r8`.  Written with Claude (AI).
Same setup as [2026-10-07](2026-10-07.md); the "all off" rows are from that report.

## What changed

- **K1 v3** (`0001`): in the `fp8` mode, the activation channels with the largest values (64 per input batch by default,
  `GGML_LF_KQ_BLAS_FP8_KEEP`) get a second fp8 term for their weight and activation rounding errors, appended to the K dimension
  of the same GEMM.  The fp8 error concentrates in a few large activation channels (the largest is 30-110x the median at the
  `ffn_down` input of Qwen3.8-27B), so correcting those channels removes a large part of it.  `GGML_LF_KQ_BLAS_FP8_KEEP=0` gives
  exactly the v2 output.
- **F8 v3.2** (`0002`): with `GGML_LF_FA_FP8` on, rdna-boosts' flash-attention F16 staging copy is capped at 1 MiB unless
  `GGML_CUDA_FA_STAGE_MAX_MB` is set.  Same output and speed; the copy (it only grows, about 1.2 GB at 240K context, and on Windows
  it lands in shared memory) is no longer made.

|---|---|---|---|---|---|---|---|

- K1 v3 costs no measurable prefill speed here (1954 against 1958); the Q5 KLD drops from 0.0047 to 0.0034.
- MXFP4 gives the same tokens as on 10-07: its weights take M4, which K1 v3 does not change.
- 3 rounds, identical tokens in every round; run-to-run CV: prefill 0.7-1.6%, decode 1.2-1.3%.

## KLD of K1 alone

Official UD-Q5_K_M; reference = plain r8 (rdna-boosts' own int8 matmul); long texts: Chinese = *Dream of the Red Chamber* (public domain), English = the
llama.cpp documentation concatenated (MIT); 48,000-token
prefix, then 400 tokens on the decode path; F8 off.

| | zh | en |
|---|---|---|
| K1 f16 | 0.0018 | 0.0006 |
| K1 fp8 v2 | 0.0027 | 0.0010 |
| **K1 fp8 v3** | **0.0023** | **0.0008** |

The error above `f16` drops by 44% (zh) and 55% (en).

## Perplexity with every position on the prefill path

Measured on the r45 port of the same patches (same output as on r8), same texts, first 30,400 tokens of each, every token scored from the prefill batch (2048 tokens per batch),
against an f32 GEMM reference of the same model.  This scores the prefill's own logits.  A server prefill computes logits only for
the last position; the generated tokens read the prompt through the KV cache, where the error is far smaller (the KLD above).

| | UD-Q5_K_M zh | en | UD-Q4_K_XL zh | en |
|---|---|---|---|---|
| plain rdna-boosts (int8 matmul) | +0.25% | +0.02% | — | — |
| K1 f16 | 0.00% | 0.00% | 0.00% | 0.00% |
| K1 fp8 v2 | +3.05% | +0.25% | +2.92% | +0.29% |
| **K1 fp8 v3** | **+2.61%** | +0.27% | **+2.32%** | **+0.14%** |

- `fp8` raises the prefill-path perplexity of Chinese text by 2-3% (English 0.1-0.3%); v3 removes 15-20% of that.  The output
  layer is not the cause (computing it in f16 changes about 0.1%).
- If a workload scores prompt tokens (perplexity runs, prompt log-probabilities), use `f16`.

# 2026-10-12 基準

本報告由 Claude（AI）撰寫。patch：`0001-a55-k1-v3`、`0002-a55-f8-v3.2`、`0003-a55-m4-v2`，套在 rdna-boosts `v16-a55e952b8-r8`。條件與 [2026-10-07](2026-10-07.md) 相同；「全關」兩列沿用該報告。

## 改了什麼

- **K1 v3**（`0001`）：`fp8` 模式下，每個輸入批次挑出 activation 最大的通道（預設 64 個，`GGML_LF_KQ_BLAS_FP8_KEEP`），把這些通道的權重與 activation 的 fp8 捨入誤差，當成第二個 fp8 項接在同一次矩陣乘的 K 維度後面。fp8 的誤差集中在少數特別大的 activation 通道（Qwen3.8-27B 的 `ffn_down` 輸入，最大通道是中位數的 30～110 倍），補這些通道就能消掉一大部分。設 `GGML_LF_KQ_BLAS_FP8_KEEP=0` 時輸出和 v2 完全相同。
- **F8 v3.2**（`0002`）：開 `GGML_LF_FA_FP8` 時，除非另外設定 `GGML_CUDA_FA_STAGE_MAX_MB`，rdna-boosts 的 flash attention F16 暫存複本上限設為 1 MiB。輸出與速度相同；那份只增不減的複本（24 萬上下文約 1.2 GB，Windows 上會落到共用記憶體）不再產生。

- 3 輪輸出逐 token 相同；跑間變異：prefill 0.7～1.6%，decode 1.2～1.3%。

## 只看 K1 的 KLD

官方 UD-Q5_K_M；參考＝原版 r8（rdna-boosts 自己的 int8 矩陣乘）；公有領域長文，先 prefill 48,000 token，再走 decode 路徑 400 個 token；F8 關。

| | 中文 | 英文 |
|---|---|---|
| K1 f16 | 0.0018 | 0.0006 |
| K1 fp8 v2 | 0.0027 | 0.0010 |
| **K1 fp8 v3** | **0.0023** | **0.0008** |

比 `f16` 多出的誤差，中文減少 44%、英文減少 55%。

## 每個位置都走 prefill 路徑的困惑度

在同一組 patch 的 r45 移植版上量（輸出與 r8 相同），同樣的長文各取前 30,400 token，每個 token 都用 prefill 批次（每批 2048 token）的輸出評分，和同一模型的 f32 矩陣乘參考比較。這量的是 prefill 本身的 logits。server 的 prefill 只算最後一個位置的 logits；生成的 token 是透過 KV 快取讀到 prompt，那部分的誤差小得多（見上面的 KLD）。

| | UD-Q5_K_M 中文 | 英文 | UD-Q4_K_XL 中文 | 英文 |
|---|---|---|---|---|
| 原版 rdna-boosts（int8 矩陣乘） | +0.25% | +0.02% | — | — |
| K1 f16 | 0.00% | 0.00% | 0.00% | 0.00% |
| K1 fp8 v2 | +3.05% | +0.25% | +2.92% | +0.29% |
| **K1 fp8 v3** | **+2.61%** | +0.27% | **+2.32%** | **+0.14%** |

- `fp8` 會讓中文文字在 prefill 路徑上的困惑度增加 2～3%（英文 0.1～0.3%）；v3 消掉其中的 15～20%。原因不在輸出層（輸出層改用 f16 只差約 0.1%）。
- 如果用途是替 prompt 的 token 評分（困惑度測試、prompt 的 log-probability），請用 `f16`。
